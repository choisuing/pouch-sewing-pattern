# 사각 파우치 도안 자동 생성 — 설계 문서

작성일: 2026-08-13

## 1. 배경과 목적

지퍼가 달린 사각 파우치(박스 파우치)를 만들려면 완성 치수에서 시접과 지퍼 여유를 역산해 전개도를 그려야 한다. 계산이 까다로워 대부분 남이 그려둔 고정 크기 도안을 쓰거나, 매번 종이에 손으로 계산한다.

이 프로젝트는 **완성 치수 세 개를 넣으면 재단용 도안 PDF가 바로 나오는 웹 도구**를 만든다. 계산은 유튜브 "에셀피" 채널의 사각 파우치 도안 계산법(<https://youtu.be/7nud1soFF5Y>)을 따른다. 그 영상은 자막이 없어 화면의 손글씨 계산식을 판독해 공식을 옮겼고, 영상의 검산값(43cm × 49cm)으로 확인했다.

UI 흐름은 <https://pattern.fingerest.co.kr>(클러치·토트백 지원)을 참고하되, 그 사이트의 코드베이스와는 무관한 별도 프로젝트다.

## 2. 범위

### 하는 것

- 가로·세로(바닥폭)·높이 입력 → 전개도 도안 생성
- 프리셋 버튼으로 대표 크기 즉시 채우기
- SVG 실시간 미리보기 (재단선·접힘선·조각 이름·치수·페이지 분할 경계)
- A4/A3 선택, 1:1 실치수 타일링 PDF 다운로드

### 하지 않는 것 (의도적 제외)

- 회원가입, 로그인, 사용 기록 수집·전송
- 겉감/안감/솜을 나눈 별도 조각 (모두 같은 본을 쓰므로 매수만 표기)
- 손잡이·택 등 부속 조각
- 시접·지퍼 값 사용자 조정 (고정값)
- 서버, 데이터베이스
- 모바일 앱

## 3. 도안 계산 모델

### 3.1 입력과 상수

| 기호 | 의미 | 단위 |
|---|---|---|
| `W` | 가로 (완성 치수) | mm |
| `D` | 세로 = 바닥폭 (완성 치수) | mm |
| `H` | 높이 (완성 치수) | mm |
| `S` | 시접 = 10 (고정) | mm |
| `Z` | 지퍼 차감 = 10 (고정) | mm |

`S`와 `Z`는 상수로 고정한다. 도안 치수에 시접이 이미 포함되므로 **사용자는 시접을 더할 필요 없이 그대로 재단한다.**

### 3.2 전개도 구조

전개도는 한 장짜리 좌우 대칭 도형이며, 위에서 아래로 5개 밴드로 구성된다. 앞판·뒤판 밴드가 좌우로 `H/2`씩 좁아 전체 실루엣이 오목한 H자 형태가 된다. 이 오목한 부분이 접혀 파우치의 옆면이 된다.

| # | 밴드 | 폭 | 높이 |
|---|---|---|---|
| 1 | 윗단 (지퍼단) | `W + H + 2S` | `D/2 − Z/2 + 2S` |
| 2 | 앞판 | `W + 2S` | `H − 2S` |
| 3 | 바닥 | `W + H + 2S` | `D + 2S` |
| 4 | 뒤판 | `W + 2S` | `H − 2S` |
| 5 | 윗단 (지퍼단) | `W + H + 2S` | `D/2 − Z/2 + 2S` |

- 전체 폭 = `W + H + 2S`
- 전체 높이 = `2D + 2H − Z + 2S`
- 앞판·뒤판의 좌우 들여쓰기 = `H / 2` (각 변)

앞판·뒤판 높이가 `H − 2S`로 **줄어드는** 것은 직관과 반대로 보이지만 영상 계산법 그대로다. 위아래로 이어지는 밴드와 시접을 공유하기 때문이다.

### 3.3 검산 (골든 케이스)

영상 예시 `W=270, D=100, H=140`:

- 전체 폭 = 270 + 140 + 20 = **430mm** (영상: 43cm)
- 전체 높이 = 200 + 280 − 10 + 20 = **490mm** (영상: 49cm)
- 밴드 높이: 65 + 120 + 120 + 120 + 65 = **490mm** — 전체 높이와 일치
- 앞판 폭 = 290mm, 좌우 들여쓰기 = 70mm

"밴드 높이의 합 = 전체 높이"는 임의의 입력에 대해 항상 성립하는 불변식이며, 테스트로 고정한다.

### 3.4 유효 범위

수학적 최소 조건은 `H > 2S`(높이가 20mm 초과)와 `D > 0`이지만, 실제로 적용하는 제한은 아래 실용 범위다. 실용 범위가 수학적 조건보다 엄격하므로 검증은 실용 범위만 확인하면 된다.

| 입력 | 최소 | 최대 |
|---|---|---|
| `W` 가로 | 100mm | 400mm |
| `D` 세로(바닥폭) | 40mm | 200mm |
| `H` 높이 | 60mm | 300mm |

범위를 벗어난 입력은 거부하고 다운로드를 잠근다.

### 3.5 소수점 처리

입력은 **정수 mm만** 받는다. 다만 `D`가 홀수면 `D/2`에서 0.5mm가 생기므로 **내부 계산과 좌표는 반올림하지 않고 소수를 그대로 유지한다.** 밴드 높이를 각각 반올림하면 "밴드 높이 합 = 전체 높이" 불변식이 깨져 도안에 틈이나 겹침이 생긴다. 반올림은 화면·도면에 치수를 **표시할 때만** 적용하며, 소수 첫째 자리까지 보여준다.

## 4. 구조

### 4.1 모듈 경계

계산·타일링·PDF 생성은 DOM과 `window`를 전혀 참조하지 않는 순수 모듈로 둔다. UI는 그 위에 얹는다.

```
src/
  core/                 # 브라우저 무관 — Node/CLI/서버에서 그대로 재사용
    constants.ts        # S, Z, 입력 허용 범위, 프리셋
    dimensions.ts       # 입력 검증 → 정규화된 Dimensions
    layout.ts           # Dimensions → Piece[] (밴드·선분 좌표, 전부 mm)
    tiling.ts           # Piece[] + 용지 → Page[] (분할·겹침·정렬 마크)
    pdf.ts              # Page[] → Uint8Array (pdf-lib)
  ui/
    preview.ts          # Piece[] → SVG 미리보기
    form.ts             # 입력칸·프리셋 버튼·용지 선택
  main.ts               # 조립만 담당
```

의존 방향은 단방향이다. `ui`는 `core`를 부르지만 `core`는 `ui`를 모른다. 미리보기와 PDF가 **같은 `layout.ts` 결과**를 소비하므로 화면과 출력이 어긋날 수 없다.

### 4.2 데이터 흐름

```
입력값 → dimensions.validate() → Dimensions
       → layout.build()        → Piece[]
       → tiling.paginate()     → Page[]  ─┬→ preview.render(Piece[], Page[]) → SVG
                                          └→ pdf.build(Page[])               → Uint8Array → 다운로드
```

미리보기가 페이지 분할 경계를 함께 그리므로 `tiling`은 PDF 생성 전에, 입력이 바뀔 때마다 실행된다. 미리보기와 PDF가 동일한 `Page[]`를 소비하므로 화면에 보이는 장수와 실제 출력 장수가 어긋날 수 없다.

### 4.3 기술 스택

- Vite + TypeScript (프레임워크 없음)
- `pdf-lib` — PDF 생성
- `vitest` — 테스트

### 4.4 호스팅 유연성

- **정적 산출물만** — `vite build` → `dist/`. Nginx, S3, GitHub Pages, 사내 서버 어디든 복사하면 동작한다.
- **상대 경로 고정** (`base: './'`) — `example.com/pouch/` 같은 하위 경로에 배포해도 동작한다.
- **외부 의존 0** — CDN 스크립트, 웹폰트, 외부 API를 쓰지 않는다. 폐쇄망·오프라인에서도 동작한다.
- 나중에 서버 렌더링이 필요해지면 `core`를 Node에서 import해 엔드포인트를 만들 수 있고, 프런트는 손대지 않는다.

## 5. PDF 타일링

### 5.1 배치

- 단위 변환: 1mm = 2.83465pt, **1:1 실치수**
- 용지: A4(210×297) 또는 A3(297×420). 각 용지의 세로·가로 방향 중 **장수가 적은 쪽을 자동 선택**
- 인쇄 여백: 사방 8mm (프린터 비인쇄 영역 대비)
- 페이지 간 겹침: 10mm — 잘라 붙일 여유

### 5.2 각 페이지에 넣는 것

- 정렬용 십자 마크 (겹침 영역 모서리)
- 격자 번호 — 행은 문자, 열은 숫자. 왼쪽 위가 `A1`, 그 오른쪽이 `A2`, 아래가 `B1`
- **50mm 검증 눈금자** — 인쇄물을 자로 재서 50mm가 아니면 "페이지 맞춤"이 켜진 것이다. 종이를 버리기 전에 사용자가 알아챌 수 있게 한다.
- 첫 페이지에 전체 배치 축소도 (붙이는 순서 안내)

### 5.3 페이지 수 계산

타일 간격 = (용지 사용 가능 크기 − 겹침). 페이지 수는 전개도 전체 크기를 이 간격으로 나눠 올림한다. 타일들의 합집합이 전개도 전체를 덮는지 테스트로 검증한다.

## 6. 화면

### 6.1 구성

1. 프리셋 버튼 — 필통 `200×60×60`, 화장품 파우치 `220×90×130`, 여행 파우치 `270×100×140`
2. 가로·세로·높이 입력칸 (mm)
3. SVG 미리보기 — 재단선(실선), 옆면 접힘선(점선), 조각 이름(지퍼단/앞판/바닥/뒤판), 주요 치수, 페이지 분할 경계(옅게)
4. 용지 선택 (A4 / A3) — 각 선택지에 예상 장수 표시
5. PDF 다운로드 버튼

### 6.2 에러 처리

| 상황 | 처리 |
|---|---|
| 입력이 비었거나 숫자가 아님 | 해당 칸 아래 메시지, 다운로드 잠금 |
| 허용 범위를 벗어남 | 허용 범위를 알려주는 메시지, 다운로드 잠금 |
| 페이지 수가 20장 초과 | 다운로드 전 경고 (진행은 가능) |
| PDF 생성 실패 | 화면에 오류 메시지 표시 — 조용히 실패하지 않는다 |

## 7. 테스트

TDD로 진행한다. 모든 테스트는 `vitest`로 돌린다.

| 대상 | 검증 내용 |
|---|---|
| `dimensions` | 경계값 — 각 입력의 최소 −1 거부·최소 허용, 최대 허용·최대 +1 거부 (예: `H=59` 거부, `H=60` 허용, `H=300` 허용, `H=301` 거부). 정수가 아닌 값 거부 |
| `layout` | 골든 케이스 `270/100/140` → 430×490 및 각 밴드 치수. 임의 입력에 대해 "밴드 높이 합 = 전체 높이" 불변식 |
| `tiling` | 페이지 수 계산, 겹침 적용, 타일 합집합이 전개도 전체를 덮음, A4/A3 장수 비교 |
| `pdf` | 산출물이 PDF 헤더로 시작, 페이지 수가 `tiling` 결과와 일치, 페이지 크기가 지정 용지와 일치 |

## 8. 미해결 사항

영상에 자막·음성 대본이 없어 다음은 확인하지 못했다. 도안 치수 계산에는 영향이 없다.

- 겉감·안감·솜 각각의 매수와 봉제 순서
- 윗단 밴드 안에 그려진 세로 구분선의 정확한 용도 (지퍼 물림 위치로 추정)

봉제 순서 안내가 필요해지면 별도 작업으로 다룬다.
